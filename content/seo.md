# SEO

Настраивать ничего не нужно: у каждой страницы уже есть всё, что читают поисковики. Ниже — что именно и чем на это можно повлиять из заметки.

## Что сайт делает сам

- каждая заметка — отдельная страница с чистым адресом;
- заголовок, описание, картинка для соцсетей и основной адрес страницы (canonical) записываются в каждую страницу;
- карта сайта (`sitemap.xml`) перечисляет все страницы и для каждой — дату последнего изменения: сборка берёт её из истории репозитория, то есть из дня, когда вы последний раз меняли заметку;
- `robots.txt` разрешает поисковикам обход;
- страницы связаны между собой: разделы, «Связанные материалы», ссылки `[[…]]` из текста.

## Свойства заметки, которые влияют на поиск

| Свойство | Что делает |
|---|---|
| `title` | заголовок страницы и строка в выдаче |
| `description` | описание под заголовком в выдаче; лучше 50–200 знаков |
| `seo_title` | отдельный заголовок для выдачи, если `title` длинный (до 70 знаков) |
| `updated` | дата изменения, если хотите указать её сами, например `2026-10-21` |
| `noindex` | `true` — страница есть на сайте, но не попадает в поиск и карту сайта |
| `draft` | `true` — черновик: в карту сайта и поиск по сайту не попадает |

## Что проверяет сборка

При каждой публикации сборка печатает в журнале GitHub Actions подсказки: у какой страницы нет описания, где заголовок слишком длинный, у каких страниц одинаковые заголовки или описания, на какую страницу не ведёт ни одна ссылка. Это предупреждения — сайт публикуется в любом случае.

## Как работает перелинковка

Когда вы ставите ссылки между заметками, вы усиливаете структуру сайта и облегчаете обход для поисковых систем. Страница, на которую не ведёт ни одна ссылка, находится только через карту сайта.
